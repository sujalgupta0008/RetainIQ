# Security Policy — RetainIQ

## Supported versions
`main` plus the current `audit/*` hardening line. Demo project — no SLA; report issues
via GitHub Issues.

## What this app is / isn't
RetainIQ is a **demo** retention-analytics app (synthetic data, simulated campaign outcomes).
It is NOT hardened for production handling of real customer PII. All money figures are
**estimates**; campaign "results" are simulated against a control split.

## Secrets — ROTATE / SET THESE
Set via environment (see `.env.example`); never commit real values:

| Name | Status |
|---|---|
| `JWT_SECRET` | MUST be a long random string (≥32 bytes). App refuses `prod` start on the dev default. **If the default was ever used in a shared/staging env, rotate it — all issued tokens invalidate.** |
| `GEMINI_API_KEY` / `OPENAI_API_KEY` | Optional. When set, aggregate customer data is sent to that provider per AI-analyst request. Unset to keep everything local (deterministic fallback). |
| `DATABASE_URL` | Use Postgres with a strong password in prod; SQLite files must not be committed. |

## Auth & tenant model (post-audit)
- Passwords: PBKDF2-HMAC-SHA256 100k + per-user salt; min length 8 (enforced at registration).
- Open registration can only create `manager|analyst|viewer` — never `admin`.
- Tenant switching (`POST /api/auth/switch`) is **admin-only**. It still mutates the user row
  (demo simplification); production needs a membership table + session-scoped switch.
- JWT: HS256, 24h expiry, `iat` claim; stored in `localStorage` by the SPA (XSS-stealable —
  production should use httpOnly cookies + CSRF protection).
- Rate limiting is in-process/memory only (single instance). Use Redis / gateway limits in prod.

## Upload & model safety
- CSV uploads: `.csv` only, ≤5 MB, ≤20k rows, ≤100 cols; parsed with bounded reads.
- ML artifacts (`backend/ml/artifacts/*.pkl`) are pickles: only deploy files generated by
  `python -m backend.ml.train` from trusted data. `train.py` writes `.sha256` sidecars that
  `infer.py` verifies when present; mismatches fall back to the rule model.

## Reporting a vulnerability
Open a GitHub issue titled `[SECURITY]` with: affected endpoint/file, repro steps, impact.
Do not post secrets or real customer data. Expect a best-effort response; no bounty.
